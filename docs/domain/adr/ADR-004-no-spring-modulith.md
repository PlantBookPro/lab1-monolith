# ADR-004: Архитектурные правила — ArchUnit, без Spring Modulith

Статус: принято и реализовано (итерация 0).

## Контекст

Границы bounded contexts должны проверяться автоматически (раздел 10.2
требований). Spring Modulith допустим как дополнение, если совместим с Boot.

## Решение

- Только **ArchUnit 1.5.0** (`archunit-junit6`, т.к. Boot 4.0.8 управляет
  JUnit Jupiter 6.0.3).
- Все 9 правил раздела 10.2 покрыты тестами:
  - `ContextBoundaryTest`: отсутствие циклов; зависимости между контекстами
    только из адаптеров и только в `api`; допустимые направления по context map
    (отдельное правило на каждое запрещённое направление); только `config` знает
    несколько контекстов.
  - `LayerRulesTest`: иерархия слоёв `domain` ← `application` ← `adapter`;
    чистота `domain` от инфраструктуры; JPA-сущности и Spring Data репозитории
    только в `adapter.out.persistence`; контроллеры не трогают домен и
    репозитории; `shared` не зависит от контекстов и `config`.

## Альтернатива

Spring Modulith (`ApplicationModules.verify()`): дополнительная зависимость,
риск несовместимости с линией Boot 4.0.x, дублирование правил ArchUnit.

## Последствия

- `archunit.properties` с `failOnEmptyShould=false` — временное упрощение
  итерации 0 (пакетов контекстов ещё нет), удаляется в итерации 9.
