# ADR-003: Flyway — каталог и история миграций на контекст

Статус: принято и реализовано (итерация 0).

## Контекст

Одна PostgreSQL со схемой на контекст; при выделении контекста в сервис (лаба №2)
его миграции должны переноситься без переименований (раздел 11 требований).

## Решение

- У каждого контекста свой каталог `classpath:db/migration/<context>`.
- У каждого контекста своя `flyway_schema_history` **в своей схеме**.
- Несколько Flyway-запусков выполняет `config.SchemaMigrationConfig` (ADR-003):
  упорядоченный список схем `CONTEXT_SCHEMAS` = identity, media, plants,
  moderation, tournaments, geo, feed; миграции выполняются при создании бина,
  до авто-конфигурации `EntityManagerFactory`, поэтому Hibernate `ddl-auto=validate`
  видит уже мигрированные схемы.
- Авто-миграция Boot отключена (`spring.flyway.enabled=false`).
- Миграции итераций 1–9 кладутся в эти каталоги с нумерацией `V2__`, `V3__` …
  в своём каталоге; таблицы контекста создаются в своей схеме, межсхемных FK нет.

## Последствия

- Выделение сервиса: каталог `db/migration/<context>` и схема переносятся как есть.
- Контракт зафиксирован тестом `SchemaMigrationIT`.
