# ADR-005: Демо-идентификация через X-Demo-User-Id

Статус: принято (итерация 0, реализация — итерация 1).

## Контекст

Настоящая аутентификация (Spring Security + JWT) — лаба №3. Для лабы №1 нужен
способ идентификации пользователя в dev/test/demo-сценариях через Swagger UI
(раздел 2 требований).

## Решение

- Заголовок `X-Demo-User-Id` разрешён **только в профилях `dev` и `test`**.
- Пользователь и его роли извлекаются из БД по ID; **роли из заголовка не
  принимаются**.
- Отсутствие заголовка = гость; неизвестный/неактивный ID = ошибка.
- `CurrentActor` (userId, роли, признак гостя) — технический тип в
  `shared.security`; провайдер реализует контекст identity.
- Обычный профиль без адаптера идентификации завершается **явной ошибкой
  конфигурации при старте**.
- Механизм описан в Swagger; это механизм демонстрации, не аутентификация.

## Последствия

- Лаба №3: заменяется только адаптер провайдера `CurrentActor` на JWT
  (`Authorization: Bearer ...`); `AccessPolicy` контекстов и их тесты не меняются.
- Пароль: во входном DTO создания учётной записи разрешён с лабы №1, хранится
  только хэш за портом `PasswordHasher`; никогда не присутствует в ответах,
  списках, логах и Entity-сериализации.
