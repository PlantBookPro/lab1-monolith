# ADR-016: Демо-идентификация сквозь сервисы; internal-эндпоинты доверенные

Дата: 2026-10-23. Статус: принято (лаба №2).

## Контекст

ADR-005: в dev/test субъект передаётся заголовком `X-Demo-User-Id`, роли
всегда из БД identity. В монолите CurrentActor разрешался in-process. В
лабе №2 публичные API разнесены по сервисам, а JWT — лаба №3.

## Решение

- **Каждый сервис сам разрешает актёра**: web-фильтр читает
  `X-Demo-User-Id` из входящего запроса и вызывает identity
  `GET /internal/actors/{userId}` (Feign). Отсутствие заголовка — гость;
  неизвестный/деактивированный — 401 `NOT_IDENTIFIED` (Feign 404 →
  NotIdentifiedException).
- **Заголовок не пробрасывается сервис→сервис**: межсервисные вызовы идут
  от сервиса, а не от пользователя; внутренние команды несут userId
  явно в теле/пути (контракт, а не контекст запроса).
- **`/internal/**` — доверенные эндпоинты без аутентификации**: вызываются
  только соседними сервисами внутри сети; gateway не маршрутизирует
  `/internal/**` (маршрут `/api/v1/internal/**` — demo-ручка tournaments,
  dev/test, M/A). Порты сервисов опубликованы только для локальной
  отладки (docker-compose).

## Последствия

- Один лишний Feign-вызов identity на запрос с идентификацией — принято
  для демо; лаба №3 (JWT) уберёт его: локальная проверка токена.
- Доверие сети — осознанное упрощение лабы: mTLS/service-токены не
  требуются заданием.
- Гостевые сессии проверяются в tournaments (владелец агрегата —
  ADR-013), не в identity.
