# ADR-002: Лента — собственная read-модель (проекция)

Статус: принято (итерация 0, реализация — итерация 8).

## Контекст

Лента должна смешивать карточки глобального и закрытых турниров, фильтроваться
по правам субъекта, сортироваться псевдослучайно и пагинироваться курсором без
total (раздел 9 требований). Feed не имеет права читать чужие таблицы напрямую.

## Решение

- **Собственная read-модель**: схема `feed`, таблица карточек, обновляемая
  опубликованными событиями контекстов-владельцев (`tournaments`, `plants`,
  `media`, `identity`).
- **Псевдослучайный sort key вычисляется в SQL** от server-issued seed и
  стабильного ID — таблица не грузится в память, стоимость сортировки
  документируется.
- **Keyset-пагинация**: value object `FeedCursor` (seed, snapshotCutoff,
  lastSortKey, lastId, субъект, фильтры), защищён HMAC от подмены. Невалидный
  cursor → 400, истёкший → 410. Никакого OFFSET поверх `ORDER BY random()`.
- Любая выдача повторно фильтруется по правам: cursor не даёт права на чужую ленту.

## Альтернативы

- Read-порты к `api` владельцев на каждый запрос: N+1 запросов, сложная
  keyset-пагинация через границы контекстов.

## Последствия

- Эволюция в лабе №4: outbox → Kafka → проекция — меняется только доставка
  событий, read-модель и курсор остаются.
